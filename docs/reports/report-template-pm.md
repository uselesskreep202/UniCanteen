## Отчёт о работе (100–400 слов)

В роли менеджера проекта я координировал работу команды из 5 человек над веб-приложением UniCanteen — системой предзаказа в университетской столовой.

**Организация процесса:**  
Выбрали методологию Kanban с итерациями по 2–3 дня. Создал доску задач в GitHub Projects, декомпозировал проект на 25+ задач, назначил ответственных. Настроил правило обязательного Pull Request перед мержем в `develop`.

**Аналитическая работа:**  
Собрал и задокументировал требования к системе. Написал PRD с функциональными (20 требований) и нефункциональными (8 требований) критериями. Разработал диаграмму классов (8 классов, 6 связей) и диаграмму последовательностей для процесса оформления заказа.

**Ход работы:**  
— Дни 1–2: настройка репозитория, декомпозиция задач, начало разработки  
— Дни 3–5: активная разработка всех модулей параллельно  
— Дни 6–7: тестирование, исправление дефектов, code review  
— День 8: интеграция, финальная проверка CI, запись видео-демо  
— День 9–10: подготовка презентации, сдача отчётов  

**Результат:**  
Реализовано 100% приоритетных требований. Приложение задеплоено, CI/CD настроен, покрытие тестами ≥ 60%. Команда уложилась в срок.

## Ход работы над проектом

### Методология
**Kanban** с элементами Agile. Задачи декомпозированы и разбиты по исполнителям. Статусы: To Do → In Progress → Review → Done.

### Модель жизненного цикла
**Итеративная модель** — разработка идёт короткими циклами с постоянной интеграцией.

### Принятые архитектурные решения
| Решение | Обоснование |
|---------|-------------|
| FastAPI вместо Django | Быстрее для REST API, автодокументация |
| PostgreSQL вместо MySQL | Лучшая поддержка JSON, более строгая типизация |
| JWT вместо сессий | Stateless, подходит для SPA |
| Zustand вместо Redux | Меньше boilerplate кода |
| Repository Pattern | Изоляция слоёв, упрощает тестирование |
